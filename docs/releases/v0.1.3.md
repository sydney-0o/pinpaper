# Pinpaper v0.1.3

## English

- Fixed a Linux startup crash path in WebKitGTK's GBM/EGL renderer. Pinpaper now reads the loaded WebKitGTK runtime version before Tauri/GTK startup and enables the compatible fallback for that runtime.
- WebKitGTK versions before 2.42 use the broad `WEBKIT_DISABLE_DMABUF_RENDERER=1` fallback; versions 2.42 and newer use the narrower `WEBKIT_DMABUF_RENDERER_DISABLE_GBM=1` fallback.
- Existing user values for either WebKitGTK variable are preserved.
- All desktop packages are rebuilt from the same versioned source. macOS remains ad-hoc signed and is not presented as Developer ID signed or notarized.

### macOS first launch

The macOS DMGs are ad-hoc signed, not signed with an Apple Developer ID certificate, and not notarized by Apple. A complete ad-hoc signature does not make the app trusted by Gatekeeper on every macOS version.

1. Download the DMG for your processor from this release and compare its SHA256 value with `SHA256SUMS.txt`.
2. Open the DMG and drag Pinpaper to Applications.
3. Try to open Pinpaper once.
4. If macOS blocks it, open **Apple menu → System Settings → Privacy & Security → Open Anyway**, then confirm **Open** after checking the source and checksum. This is a per-app approval; do not disable Gatekeeper globally.

The CI `codesign --verify --deep --strict` check covers the app inside each final DMG. `spctl` may still reject an ad-hoc, non-notarized build; that result is expected and is not presented as Apple trust.

## Русский

- Исправлен путь падения Linux при запуске WebKitGTK с GBM/EGL. Теперь Pinpaper читает версию уже загруженного WebKitGTK до запуска Tauri/GTK и выбирает совместимый fallback.
- Для WebKitGTK младше 2.42 используется общий fallback `WEBKIT_DISABLE_DMABUF_RENDERER=1`; для версии 2.42 и новее — более узкий `WEBKIT_DMABUF_RENDERER_DISABLE_GBM=1`.
- Если пользователь уже задал одну из переменных WebKitGTK, её значение и значение второй переменной не перезаписываются.
- Все desktop-пакеты пересобраны из одного источника версии. macOS по-прежнему подписан ad-hoc и не выдаётся за сборку с Developer ID или нотариальной проверкой Apple.

### Первый запуск на macOS

DMG-файлы macOS подписаны ad-hoc, но не подписаны сертификатом Apple Developer ID и не прошли нотариальную проверку Apple. Полная ad-hoc-подпись не делает приложение доверенным для Gatekeeper на каждой версии macOS.

1. Скачайте DMG для своего процессора со страницы этого релиза и сравните SHA256 с `SHA256SUMS.txt`.
2. Откройте DMG и перетащите Pinpaper в «Программы».
3. Один раз попробуйте запустить Pinpaper.
4. Если macOS заблокировала запуск, откройте **Apple → Системные настройки → Конфиденциальность и безопасность → Открыть всё равно**, затем подтвердите **Открыть** после проверки источника и контрольной суммы. Это разрешение только для приложения; не отключайте Gatekeeper глобально.

Проверка CI `codesign --verify --deep --strict` охватывает приложение внутри каждого итогового DMG. `spctl` всё ещё может отклонить ad-hoc-сборку без нотариальной проверки; это ожидаемо и не выдаётся за доверие Apple.
